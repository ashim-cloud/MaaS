=======================================================================
  Zabbix Server (Native HA) — Deployed Successfully
=======================================================================

Namespace:   {{ .Release.Namespace }}
Version:     {{ .Values.zabbix.version }}
Image:       {{ include "zabbix-server.image" . }}
HA Replicas: {{ .Values.zabbixServer.replicaCount }}

-----------------------------------------------------------------------
  1. Check Zabbix Server HA Status
-----------------------------------------------------------------------

  # Wait for pods to be ready
  kubectl get pods -n {{ .Release.Namespace }} -l app=zabbix-server -o wide

  # Check HA node status
  kubectl exec -n {{ .Release.Namespace }} {{ include "zabbix-server.statefulSetName" . }}-0 \
    -- zabbix_server -R ha_status

  # Verify HA labels (one pod should be "active", rest "standby")
  kubectl get pods -n {{ .Release.Namespace }} -l app=zabbix-server --show-labels

-----------------------------------------------------------------------
  2. Get NLB Address (for external agent clients)
-----------------------------------------------------------------------

  kubectl get svc {{ include "zabbix-server.activeServiceName" . }} \
    -n {{ .Release.Namespace }} \
    -o jsonpath='{.status.loadBalancer.ingress[0].hostname}'

  External agents should connect to this hostname on port 10051.

-----------------------------------------------------------------------
  3. Check HA Sidecar Logs
-----------------------------------------------------------------------

  # View sidecar logs for HA role changes
  kubectl logs -n {{ .Release.Namespace }} {{ include "zabbix-server.statefulSetName" . }}-0 \
    -c ha-label-sidecar --tail=20

  kubectl logs -n {{ .Release.Namespace }} {{ include "zabbix-server.statefulSetName" . }}-1 \
    -c ha-label-sidecar --tail=20

-----------------------------------------------------------------------
  4. Check SSM Init Logs (if pods are not starting)
-----------------------------------------------------------------------

  kubectl logs -n {{ .Release.Namespace }} {{ include "zabbix-server.statefulSetName" . }}-0 \
    -c ssm-init

-----------------------------------------------------------------------
  PREREQUISITES REMINDER
-----------------------------------------------------------------------

  This chart assumes the following already exist:

  1. Namespace: {{ .Release.Namespace }}
     kubectl create namespace {{ .Release.Namespace }}

  2. SSM parameters under: {{ .Values.zabbixServer.ssmInit.parameterPath }}
     Required keys: host, port, dbname, user, password

  3. IAM role with permissions:
     - ssm:GetParameter* on the DB credential parameters
     - kms:Decrypt on the KMS key

  4. EKS Pod Identity association for ServiceAccount:
     {{ include "zabbix-server.serviceAccountName" . }}

  5. RDS PostgreSQL database reachable from the EKS cluster.

=======================================================================
